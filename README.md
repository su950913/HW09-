# HW09 兩場活動報名整理器

### 1. 集合（Set）概念與「人數 vs. 人次」說明

* **交集 (Intersection `&`)**：同時報名「活動 A」且報名「活動 B」的名單。代表兩場都想參加的人。
* **聯集 (Union `|`)**：報名「活動 A」或報名「活動 B」的名單（去重後）。代表這次活動總共服務了多少個「不同」的人。
* **差集 (Difference `-`)**：
  * **A - B (A 差集 B)**：只有報名「活動 A」，但沒有報名「活動 B」的名單。
  * **B - A (B 差集 A)**：只有報名「活動 B」，但沒有報名「活動 A」的名單。
* **人數 (Unique Users) vs. 人次 (Total Registrations)**：
  * **人次**：不排除重複。如果同一個人報名了活動 A 也報名了活動 B，或是單一活動重複報名，每次報名都算一次（例如：活動 A 報名 5 次 + 活動 B 報名 4 次 = 9 人次）。
  * **人數**：排除重複。透過 `set` 進行去重，計算實際上有多少個「獨立的個體」（不重複的姓名）參與。

**問題一 : 測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？**
為什麼桌遊費用要以3 人計算？ 原始資料狀況：在測試一中，桌遊體驗整理後的原始名單為['amy', 'ben', 'amy', 'cora']，這裡面總共有4 筆報名紀錄。 重複報名規則：名單中的'amy'重複出現了兩次。根據活動主辦方的規則：「同一個人在同一場活動中重複出現，只算一位參加者，也只收一次該場費用。」 實際收費人數：剔除重複的'amy'之後，實際報名的不重複人員只有'amy'、'ben'、'cora'這3 個人。 計費公式：因此，費用必須以實際不重複的3 人來計算，即：3 人× 120 元= 360 元。

直接把字符串拆成List 保留與失去了什麼？ 保留了：重複性。每一個報名紀錄都會完整保留下來（例如可以知道'amy'報名了兩次）。 保留了：順序性。元素會完全依照使用者報名的順序排列。 失去了：唯一性。串列無法自動幫我們過濾重複的姓名，因此不能直接拿來當作計算「實際到場人數」與「應收費用」的依據。

再將List 轉換成Set 保留與失去了什麼？ 保留了：唯一性(去重)。集合會自動刪除重複的元素，只留下唯一的不重複姓名，非常適合直接拿來計算實際應收費用的「總人數」。 失去了：重複紀錄。我們無法再得知哪些姓名曾經重複報名過、重複了幾次（失去了「人次」的歷程軌跡）。 失去了：順序性。集合在Python 中是無序的，我們無法得知這些人在原始資料中誰先報名、誰後報名。
